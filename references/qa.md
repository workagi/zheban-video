# 质检标准与修复方法

阈值写在 `scripts/check.py` 和 `scripts/final_check.py` 里。**不许为了通过而放宽阈值**；只能改分镜、文案或组件参数。

## 自动检查（build.sh preview / full）
| 检查 | 标准 | FAIL 时怎么修 |
|---|---|---|
| 时长 | Σ场景秒数（或 bars × 小节）= duration（±0.05s） | 调整场景秒数或 bars |
| 首帧 | t=0 有完全可见的 title/big/quote；画面非黑 | 首场景首行 at=0；首场景不用 none 组件 |
| 钩子 | hook 存在，≤ 16 字（超过是 WARN） | 压缩成问句 |
| 溢出 | 缩到最小字号仍放不下 = FAIL | 删字，或手动 `\n` 断行 |
| 安全区 | 横屏四周 5%；竖屏上 12%、下 20%、左 72px、右 120px（避开平台按钮） | 换 layout；缩短文案 |
| 最小字号 | 横屏：标题 64 / 正文 48 / 小字 30 / 脚注 22；竖屏：72 / 56 / 36 / 26 | 删字，不要改 size 倍率压小 |
| 遮挡 | 同一时刻两段可见文字相交 > 4% | 同 role 的行用 at/out 接力；组件标签太长就缩短 |
| 对比度 | 标题/小字 ≥ 3.0，正文（sub/caption/code）≥ 4.5（文字隐藏后对文字框背景取 25/75 分位，忽略穿过的细线） （转场叠化窗口内不计；须持续 ≥0.2 秒才算）| 换 layout 避开亮部；开 textBed；文字别压在高亮面板上 |
| 读速 | ≤ 5 字/秒（> 4.5 WARN）；每行可见 ≥ 1 秒 | 延后 out、缩短文案、给场景加小节 |
| 转折间隔 | 相邻 turn ≤ turnMax（默认 15 秒） | 在长段落中间拆出新场景并标 turn |
| 结尾 | 最后场景有 quote/title | 补落点句 |
| 来源记录完整性 | facts.md 存在且 ≥ 2 个不同链接（不等于核实了事实）；含数字的行要有 src 或在 facts.md 写了场景 id（缺了是 WARN） | 补 facts.md |

## 成片检查（final_check.py）
H.264 High / yuv420p · 分辨率 · 30fps · 时长 ±0.15s · AAC 48kHz · 响度 -14 ±1 LUFS · 真峰值 ≤ -1 dBTP · 末 0.25 秒 < -35 dB（淡出）· 首帧按解码后的全范围 RGB 检查（平均亮度 >3/255 且 >12/255 的像素至少1%，避免 YUV 黑位16误判） · 全片解码成功 · 生成 qa/overview.jpg。无声预览用 `--silent`，要求零音轨并跳过音频指标。

## 人工目检（看 keyframes_sheet.jpg 和 overview.jpg，逐条回答）
1. **层次**：每帧都能分出背景（布景）/ 中景（组件）/ 前景（粒子、光球、梅枝等）吗？
2. **主体**：一眼能看出这一屏讲什么吗？同一时刻只有一个主动画吗？
3. **遮挡**：组件有没有压到文字、钩子条或字幕带？
4. **构图**：留白均衡吗？左右布局时文字和组件的视觉重量平衡吗？
5. **曝光**：暗部有层次（不是死黑）、亮部不过曝吗？浅色风格是否发灰？
6. **一致**：强调色每屏 ≤ 1 处，字体、字号、动效与预设一致吗？

## 修改轮次
- 第 1 轮：修掉所有 FAIL，再按目检 6 问改一遍（一般是文案长度、布局、组件参数）
- 修改后重渲关键帧，确认修改生效、没有引入新问题；首轮无问题时无需人为制造修改
- 两轮后仍有问题再改，最多 3 轮；每轮把「改了什么」用一两句话告诉用户

## 动态与参考对照（单独记录）

技术检查通过后，仍需检查实际动态片段与声音：

- **解释**：比较、时序、因果或变化是否可见？解释镜头是否仍主要依赖一段文字才能理解？
- **叙事**：结尾有没有用证据回答开头的问题？`turn` 字段有值不能证明真的发生了转折。
- **动作**：看前后状态与中间过程，尤其是箭头所指、数据增长、镜头交接和高亮对象。不要只看入场后的静帧。
- **视觉**：对照参考的主体占比、明暗焦点、材质厚度与构图变化，不以“有三层、粒子、金色”代替目标。
- **声音**：旁白锚点、字幕换句、答案揭晓是否同步？有无截断、音量压制或不自然停顿？参考片混音摘录应如实标注。
- **完整性**：检查实际使用的图表数据与事实记录一致，教学示意与历史实录区分清楚。

自动报告继续写技术结果；另记创作对照中的已改善点、实际不足和待用户判断项。不要给未经校准的“电影感分数”，也不要把画面有变化等同于有效解释。

## 新增报告

- preview/full 生成 `qa/information-report.md`：旁白逐句对比分镜与图解登记，范围见 [visual-coverage.md](visual-coverage.md)。没有时间轴的旧项目显示未评估。
- full/silent 自动运行 `motion_check.py`；scan 可只扫描已有 MP4。筛查孤立闪帧/近黑帧（FAIL）、非登记跳变与长静止（WARN），并生成 `qa/transitions.jpg` 切点连续帧。低分辨率帧差不能判断重影、美术或动作语义，仍要看实际画面。
- 有意闪光/硬切/停顿可在 `motionReview.intentional` 登记 `{start,end,kind:"flash"|"cut"|"hold",reason}`，全片秒数。区间应精确，不为消除报警覆盖整片。不要把 1–2 秒无新动作一概视为错误。
- 旧 bars/已有音频必须继续验证；新功能只在使用相应字段时生效。新主题先验证代表镜头，记录实际试过的组合。

自动接口回归：`python3 -B -m unittest discover -s "$SK/tests" -v`（motion 测试需要 numpy/Pillow/FFmpeg）。公开短片段做运行验证，艺术水平仍需对照实际参考与用户反馈。


## 固定镜头与模式边界

跨模型一致制作先读 [stable-production.md](stable-production.md)。`visual.type:"shot"` 使用 `engine/shots.json` 的字段契约；`productionMode:"stable"` 校验输入和逐句图解缺口，显式 `custom` 保留自由绘图。`build.sh PROJECT lock` 记录并校验渲染指纹，变更后须显式重建锁及复验。
