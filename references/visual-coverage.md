# 逐句图解与跨主题验证

分镜开头列少量必要信息点，每个写观众问题、结论、证据和画面要显示的关系。数量随内容，不为凑数加事实。

```json
{
  "informationPoints": [{"id":"lag", "question":"怎么复制？", "claim":"晚一轮复制", "source":"facts.md#rule"}],
  "scenes": [{
    "id":"copy",
    "explanations":[{"id":"lag-diagram", "line":"rule", "point":"lag", "kind":"flow", "evidence":"箭头从对方上一列连到我方下一列"}]
  }]
}
```

`explanations[].line` 对应旁白句 ID；id 对应该图解的运行时登记，point 对应信息点。kind 可写 mechanism/flow/compare/chart/source/diagram。必要的问句、标题或思考停顿可写 `{line:"question",exemptReason:"让观众先作选择"}`。不能用豁免掩盖缺失的解释。

内置 matrix/duo/timeline/bars/dots/split/code/image 会在组件调用时登记声明，区间可用 atSec/outSec 限定；这不证明参数语义正确。custom 必须在实际绘图的条件分支中调用：

```js
// 在箭头和状态都已画出的同一分支：
E.info('lag-diagram', 'flow', {x:r.x,y:r.y,w:r.w,h:r.h});
```

preview/full 写 `qa/information-report.md`：逐句统计采样中图解登记覆盖、证据说明、豁免理由和未覆盖的信息点。低覆盖仅为需要复核的提示；长时间可见的旧图可能已不相关，登记本身也不能证明图形实际画对。不要把这个比例叫知识含量或事实正确率。

人工逐句判断：拿掉屏幕关键词后，关系仍看得出来吗？箭头起终点、时间先后、比例和数据有没有错？背景慢推和粒子不计入解释。

## 资料型镜头

财经/新闻/商业解读优先考虑：整份材料建立来源 → 推近必要原句 → 对原句作单一高亮/翻译 → 展示相关比较。可以用局部构图/裁切和 custom.js 实现，先用二维卡片；不因此引入浏览器排版引擎或三维依赖。

重排原文时标注“节选重排”和原始来源，不伪造截图或报头；引文保持短小，中文解释与原话区分。高亮移动到下一行时清掉上一标注，避免堆字。来源记录仍需人工读原文核对。

## 跨主题最小验证

改公共接口后用代表不同难点的小片段验证，而非只复制上一主题：机制题检查因果与运动方向；人物/历史检查身份、时序和动作；资料/数据题检查来源、数值和对照。先验证关键镜头再扩全片。通过三个小片段只说明这些路径已验证，不能宣称任意主题同等水准。

源代码检查、自动报告和实际视频各有作用；风格与主题的组合只有被实际渲染、观看和听过，才能标为试过。技术完成度与用户对参考水准的评价分开记录。
